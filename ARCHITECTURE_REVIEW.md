# Architecture Review
Generated: 2026-08-31T15:58:33.943Z
Score: 60/100

## Summary
The codebase has a clear folder structure (components/hooks/lib/pages) and consistently good inline documentation, but it carries real architectural debt: two parallel type/contract systems for the same domain concepts, duplicated components/utilities with the same names but different APIs, and an inconsistent data-access pattern where some pages use the useLedger hook while others bypass it and call storage.ts directly. No circular dependencies were found. Addressing the duplication and unifying the state-access pattern would meaningfully raise code quality without a large rewrite.

## Issues
### Critical
- [consistency] Data access is inconsistent: some pages read/write state exclusively through the useLedger hook, while Platforms.tsx, Settings.tsx, and Wage.tsx call storage.ts (getPlatforms/savePlatforms/getEntries/getSettings/saveSettings/setItem) directly, bypassing the hook's in-memory state entirely. This can leave other screens (e.g. Home, which relies on useLedger) showing stale platforms/entries after a change made via the bypassed path, since there's no shared subscription. — Files: src/hooks/useLedger.ts, src/pages/Platforms.tsx, src/pages/Settings.tsx, src/pages/Wage.tsx / Fix: Route all reads/writes of platforms/entries/settings through useLedger (or a shared store) so every screen observes the same state; remove direct storage.ts calls from page components.
- [duplication] src/lib/validate.ts redefines MAX_AMOUNT, MAX_MINUTES, MAX_PLATFORM_NAME_LENGTH, MIN_GOAL, and MAX_GOAL as local literals instead of importing the equivalent constants (MAX_AMOUNT, MAX_MINUTES, MAX_PLATFORM_NAME, GOAL_MIN, GOAL_MAX) already defined in src/lib/constants.ts, so the two files can silently drift out of sync. — Files: src/lib/validate.ts, src/lib/constants.ts / Fix: Import the limits from lib/constants.ts in validate.ts and delete the local re-declarations.

### Warnings
- [dead_code] src/lib/contract.ts declares a large parallel type system (Ledger, Platform, Entry, RouteState, STORAGE_KEYS, COLOR_PALETTE, LIMITS, plus ~15 *Fn signature types) that duplicates and conflicts with the real domain types in src/lib/types.ts. Most of these exports (Ledger, contract-Platform, contract-RouteState, STORAGE_KEYS, COLOR_PALETTE, LIMITS, formatAmountFn, formatDateFn, parseDateFn, generateIdFn, validateAmountFn, validatePlatformNameFn, saveLedgerFn, loadLedgerFn, calculateStreakFn, calculateMonthlyTotalFn, useLedgerFn, useAppToastFn) are never consumed anywhere. Even the one that is used, `Entry` (in calc.ts/validate.ts), has a different shape (earnedAt/amountKrw) than the actually-used IncomeEntry (date/amount/expense) in types.ts, and contract's `Platform` (color/active) conflicts with types.ts's `Platform` (colorToken/archived). — Files: src/lib/contract.ts, src/lib/types.ts, src/lib/calc.ts, src/lib/validate.ts / Fix: Delete unused contract.ts exports, or fully migrate calc.ts/validate.ts off contract.ts's Entry/Platform onto lib/types.ts's IncomeEntry/Platform so there is a single source of truth for these shapes.
- [duplication] Two separate SubmitFooter component implementations exist with different props (one supports `loading`, the other doesn't) — src/components/BottomCTA.tsx and src/components/SubmitFooter.tsx both export a component named SubmitFooter. Only the BottomCTA version appears to be imported by pages (e.g. Entry.tsx imports from '@/components/BottomCTA'), leaving SubmitFooter.tsx dead and a likely source of future import confusion given the identical name. — Files: src/components/BottomCTA.tsx, src/components/SubmitFooter.tsx, src/pages/Entry.tsx / Fix: Keep a single SubmitFooter implementation (merge the `loading` support into one file), delete the other, and update any stray imports.
- [duplication] Two EmptyState components coexist — src/components/EmptyState.tsx and the EmptyState exported from src/components/StateView.tsx — with slightly different prop shapes (StateView's version accepts a custom `icon`). Pages import inconsistently: Platforms.tsx uses the standalone EmptyState.tsx while Entry.tsx/Wage.tsx/Sparkline.tsx use StateView's EmptyState. — Files: src/components/EmptyState.tsx, src/components/StateView.tsx, src/pages/Platforms.tsx, src/pages/Wage.tsx, src/pages/Entry.tsx / Fix: Consolidate into a single EmptyState component (StateView.tsx's version, since it's more widely used and supports a custom icon) and remove the duplicate file.
- [duplication] An identical `fireHaptic` try/catch wrapper (guarding generateHapticFeedback against throwing outside the Toss WebView) is copy-pasted across at least six files instead of living in one shared module. — Files: src/components/BottomCTA.tsx, src/components/ReportBody.tsx, src/pages/Entry.tsx, src/pages/Platforms.tsx, src/pages/Settings.tsx, src/pages/Home.tsx, src/pages/Wage.tsx / Fix: Extract a single `fireHaptic(type)` helper into e.g. src/lib/haptics.ts and import it everywhere instead of redefining it per file.
- [consistency] The useAppToast hook exists specifically to standardize toast open/text state and message copy, but Platforms.tsx, Settings.tsx, and Share.tsx each implement their own local `useState` for toastOpen/toastText instead of using it, defeating the purpose of the shared hook and risking inconsistent toast copy. — Files: src/hooks/useAppToast.ts, src/pages/Platforms.tsx, src/pages/Settings.tsx, src/pages/Share.tsx / Fix: Replace the local toast useState blocks in Platforms.tsx, Settings.tsx, and Share.tsx with useAppToast().

### Suggestions
- [duplication] `readMonth` and `monthLabel` helper functions are duplicated verbatim in Report.tsx and Share.tsx. — Files: src/pages/Report.tsx, src/pages/Share.tsx / Fix: Move readMonth/monthLabel into a shared module (e.g. src/lib/date.ts or a small src/lib/month.ts) and import from both pages.
- [duplication] Amount.tsx and CountUp.tsx duplicate the same wrapper markup (nowrap span, tabular-nums, formatNumber + unit via Paragraph.Text) — the only real difference is CountUp's animation state. — Files: src/components/Amount.tsx, src/components/CountUp.tsx / Fix: Extract the shared numeric-display span into a small internal component/hook that both Amount and CountUp render, parameterized by the displayed value.
- [duplication] Number/currency formatting is split across two overlapping modules — lib/format.ts (formatKRW, formatAmount, formatWage) and lib/utils.ts (formatNumber, formatCurrency) — and formatWage's body is nearly identical to formatKRW's (toLocaleString + '원' with only a null check added). — Files: src/lib/format.ts, src/lib/utils.ts / Fix: Consolidate all amount/number formatting into lib/format.ts, have formatWage call formatKRW internally, and remove the redundant formatNumber/formatCurrency from utils.ts (or re-export from format.ts).
- [naming] lib/id.ts exports both `genId` and `generateId` where generateId is a pure alias with zero other callers of genId itself, adding an unnecessary indirection layer. Separately, `ColorToken` is declared as a same-named runtime marker const in both lib/types.ts and lib/constants.ts (in addition to the type export), which is confusing given they're different module-scoped values with an identical identifier. — Files: src/lib/id.ts, src/lib/types.ts, src/lib/constants.ts / Fix: Drop the genId/generateId split and export a single named function; rename one of the two ColorToken runtime markers (or drop the constants.ts one, re-exporting types.ts's instead).
- [dead_code] TossPurchase.tsx (IAP purchase button wrapper) is exported but not imported by any page shown in the codebase. — Files: src/components/TossPurchase.tsx / Fix: If IAP isn't wired into any screen yet, either integrate it into a page (e.g. Settings) or remove it until it's needed, noting it as a documented future extension point if intentionally unused.
- [structure] The dev-only __TdsGallery.tsx page lives directly inside pages/ next to real routes, relying solely on a double-underscore naming convention (and a comment) to signal it's dev-only rather than physical folder separation. — Files: src/pages/__TdsGallery.tsx / Fix: Move dev-only pages into a pages/dev/ (or src/dev/) subfolder so production-route pages and dev tooling are visually and structurally separated.
